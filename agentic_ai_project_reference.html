Phase 2 — Memory, context management, security

Phase 2
ChromaDB RAG memory · sliding window · injection defence
The agent now remembers past findings and never overflows its context.

Three problems solved

Context overflow
tiktoken counts tokens before every call. Sliding window keeps last 10 turns. Summary compresses older turns so nothing is completely lost.
No long-term memory
Tool results are chunked (400 chars, 20% overlap) and stored in ChromaDB as embeddings. Top-K relevant chunks retrieved per query.
Prompt injection
Scraped content is sanitised before entering the prompt. Regex patterns catch "ignore previous instructions" style attacks and redact them.

Context hierarchy (what goes in the prompt, in order)

1. System prompt — static, always first, cache-friendly
2. RAG chunks — top-K retrieved from ChromaDB for this query
3. Sliding window — last 10 turns of conversation
4. Current user message
Chunking insight: Embeddings work best on small, focused text. A 5000-word article stored as one unit produces a blurry embedding that matches nothing well. Split into 400-char overlapping chunks — each chunk is semantically precise, and overlap ensures sentences at boundaries aren't lost.

Phase 3 — Two-layer caching

Phase 3
L1 in-memory + L2 Redis semantic cache
Skip the LLM entirely for repeated or similar queries. Savings become measurable.

The two-layer model

L1 — in-memory dict (LRU)
Python OrderedDict. Exact string match on (query + model). Sub-millisecond. Evicts oldest when full (max 100 entries). Wiped on restart — that's fine and expected.

Key: "{model}::{query.lower()}"
<1msprocess-localLRU eviction
L2 — Redis semantic cache
Stores (query_embedding, answer) in Redis with TTL. On lookup: embed the new query → cosine similarity against all cached entries → if best score ≥ 0.85, return cached answer. Survives restarts. Shared across future workers.
~2mssurvives restartTTL auto-expire

Semantic similarity — the key insight

The embedding model converts a query to a 384-dimensional vector. Cosine similarity between two vectors measures how close their meanings are, regardless of exact wording.

TTL design decision: Not all answers age the same way. "How does RAG work?" → stable, TTL = 24h. "Latest AI frameworks in 2025" → stale fast, TTL = 1h or skip cache entirely. In Phase 5 evals, you'll catch cases where a stale cache answer caused a hallucination.

Why routing matters

Gemini Pro costs ~47× more per token than Flash. If 70% of queries are simple lookups, routing them to Flash cuts your bill dramatically without touching answer quality.

observability/tracer.py
from langfuse import Langfuse
from langfuse.decorators import langfuse_context, observe
from config import LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY, LANGFUSE_HOST
import functools, time

_client = Langfuse(
    public_key=LANGFUSE_PUBLIC_KEY,
    secret_key=LANGFUSE_SECRET_KEY,
    host=LANGFUSE_HOST
)

def trace_llm_call(fn):
    """
    Decorator — wraps any function that calls the LLM.
    Records: input prompt, output, latency, token estimates.
    Usage: @trace_llm_call above run_agent()
    """
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.time()
        trace = _client.trace(name=fn.__name__, input=str(kwargs))
        span  = trace.span(name="llm_call")
        try:
            result = fn(*args, **kwargs)
            span.end(output=result[:500], metadata={
                "latency_ms": int((time.time() - start) * 1000),
            })
            trace.update(output=result[:200])
            return result
        except Exception as e:
            span.end(level="ERROR", status_message=str(e))
            raise
    return wrapper


def trace_tool_call(tool_name: str, query: str, result: str, latency_ms: int):
    """Log a single tool call as a Langfuse event."""
    _client.event(
        name=f"tool:{tool_name}",
        input={"query": query},
        output={"result_chars": len(result), "preview": result[:200]},
        metadata={"latency_ms": latency_ms}
    )


def flush():
    """Call at end of session to ensure all events are sent."""
    _client.flush()

evals/judge.py
import google.generativeai as genai
from config import GEMINI_API_KEY, GEMINI_FLASH_MODEL
import json, re

genai.configure(api_key=GEMINI_API_KEY)

_JUDGE_PROMPT = """You are an impartial eval judge for an AI research agent.

Given a question and the agent's answer, score it on three axes:
1. accuracy     (0-10): Is the answer factually correct?
2. completeness (0-10): Does it cover the key aspects of the question?
3. hallucination_risk (0-10): 10 = definitely hallucinated, 0 = well-grounded

Also write one sentence explaining your scores.

Reply in valid JSON only, no markdown:
{"accuracy": N, "completeness": N, "hallucination_risk": N, "reason": "..."}"""


def judge(question: str, answer: str) -> dict:
    """Score a single agent answer. Returns score dict."""
    model = genai.GenerativeModel(GEMINI_FLASH_MODEL)
    prompt = f"Question: {question}\n\nAgent answer:\n{answer}"
    try:
        resp = model.generate_content(
            [_JUDGE_PROMPT, prompt],
            generation_config={"temperature": 0}
        )
        text = resp.text.strip()
        text = re.sub(r'```json|```', '', text).strip()
        return json.loads(text)
    except Exception as e:
        return {"accuracy": 0, "completeness": 0,
                "hallucination_risk": 10, "reason": str(e)}


def keyword_check(answer: str, benchmark: dict) -> dict:
    """
    Fast deterministic check — no LLM needed.
    Returns {passed: bool, missing: list, forbidden_found: list}
    """
    answer_lower = answer.lower()
    missing = [kw for kw in benchmark["expected_keywords"]
               if kw.lower() not in answer_lower]
    forbidden = [kw for kw in benchmark.get("should_not_contain", [])
                 if kw.lower() in answer_lower]
    return {
        "passed": not missing and not forbidden,
        "missing_keywords": missing,
        "forbidden_found": forbidden
    }
evals/hallucination.py
from memory.vector_store import VectorMemory
from sentence_transformers import SentenceTransformer
from config import EMBEDDING_MODEL, HALLUCINATION_THRESHOLD
import numpy as np, re

_model = SentenceTransformer(EMBEDDING_MODEL)


def _cosine(a, b) -> float:
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9))


def extract_claims(answer: str) -> list[str]:
    """
    Split answer into individual sentences to check each claim.
    Simple heuristic: split on sentence boundaries.
    """
    sentences = re.split(r'(?<=[.!?])\s+', answer.strip())
    return [s.strip() for s in sentences if len(s) > 30]


def check_hallucination(
    answer: str,
    session_id: str,
    project_id: str
) -> dict:
    """
    For each sentence in the answer, check if it's grounded in
    the agent's retrieved source chunks (stored in ChromaDB).

    A sentence with no similar chunk in memory is a hallucination flag.
    Returns: {flagged: bool, risky_claims: list, grounded_claims: list}
    """
    memory = VectorMemory(project_id)
    claims = extract_claims(answer)
    risky, grounded = [], []

    for claim in claims:
        claim_vec = _model.encode(claim).tolist()
        # Pull top-1 from memory
        results = memory._collection.query(
            query_texts=[claim],
            n_results=1,
            where={"session_id": session_id}
        )
        docs = results.get("documents", [[]])[0]
        if not docs:
            risky.append({"claim": claim, "score": 0.0, "source": "no memory"})
            continue

        source_vec = _model.encode(docs[0]).tolist()
        score = _cosine(claim_vec, source_vec)

        if score < HALLUCINATION_THRESHOLD:
            risky.append({"claim": claim[:100], "score": round(score, 3), "source": docs[0][:80]})
        else:
            grounded.append({"claim": claim[:100], "score": round(score, 3)})

    return {
        "flagged": len(risky) > 0,
        "risky_claims": risky,
        "grounded_claims": grounded,
        "hallucination_rate": round(len(risky) / max(len(claims), 1), 2)
    }
evals/runner.py
import sqlite3, json
from datetime import datetime
from chat.service import ChatService
from agent.react_agent import run_agent
from cache.cache_manager import CacheManager
from router.model_router import ModelRouter
from evals.benchmark import BENCHMARKS
from evals.judge import judge, keyword_check
from evals.hallucination import check_hallucination
from config import DB_PATH, EVAL_PASS_THRESHOLD

PROJECT_ID = "research_agent_eval"  # separate project so evals don't pollute prod


def _init_db():
    with sqlite3.connect(DB_PATH) as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS eval_results (
                id          INTEGER PRIMARY KEY AUTOINCREMENT,
                run_ts      TEXT,
                benchmark_id TEXT,
                query       TEXT,
                answer      TEXT,
                kw_passed   INTEGER,
                accuracy    REAL,
                completeness REAL,
                hallucination_risk REAL,
                hallucination_rate REAL,
                judge_reason TEXT
            )""")


def run_evals(verbose: bool = True):
    _init_db()
    router  = ModelRouter()
    cache   = CacheManager()
    run_ts  = datetime.utcnow().isoformat()
    results = []

    print(f"\n{'='*60}")
    print(f"  EVAL RUN — {run_ts}")
    print(f"{'='*60}\n")

    for bench in BENCHMARKS:
        bid   = bench["id"]
        query = bench["query"]
        print(f"[{bid}] {query}")

        # Fresh session per benchmark so no cross-contamination
        chat = ChatService(project_id=PROJECT_ID)
        sid  = chat.get_session_id()

        model_name, _ = router.route(query)

        # Skip cache for evals — we want a real agent run every time
        chat.save_message("user", query)
        answer = run_agent(
            user_query=query,
            history=chat.build_context(),
            session_id=sid,
            project_id=PROJECT_ID,
            model_name=model_name
        )
        chat.save_message("assistant", answer)

        # ── Score it ──────────────────────────────────────────────
        kw_result   = keyword_check(answer, bench)
        llm_scores  = judge(query, answer)
        hall_result = check_hallucination(answer, sid, PROJECT_ID)

        row = {
            "run_ts": run_ts, "benchmark_id": bid, "query": query,
            "answer": answer,
            "kw_passed": int(kw_result["passed"]),
            "accuracy": llm_scores.get("accuracy", 0),
            "completeness": llm_scores.get("completeness", 0),
            "hallucination_risk": llm_scores.get("hallucination_risk", 10),
            "hallucination_rate": hall_result["hallucination_rate"],
            "judge_reason": llm_scores.get("reason", "")
        }
        results.append(row)

        with sqlite3.connect(DB_PATH) as conn:
            conn.execute("""INSERT INTO eval_results
                (run_ts,benchmark_id,query,answer,kw_passed,accuracy,
                 completeness,hallucination_risk,hallucination_rate,judge_reason)
                VALUES (:run_ts,:benchmark_id,:query,:answer,:kw_passed,
                        :accuracy,:completeness,:hallucination_risk,
                        :hallucination_rate,:judge_reason)""", row)

        status = "✓" if kw_result["passed"] else "✗"
        if verbose:
            print(f"  {status} kw={kw_result['passed']} | "
                  f"acc={row['accuracy']}/10 | "
                  f"hall_risk={row['hallucination_risk']}/10 | "
                  f"hall_rate={row['hallucination_rate']}")
            if hall_result["risky_claims"]:
                print(f"  ⚠ Risky claims:")
                for rc in hall_result["risky_claims"][:2]:
                    print(f"    - [{rc['score']}] {rc['claim']}")
        print()

    # ── Summary ───────────────────────────────────────────────────────
    passed     = sum(1 for r in results if r["kw_passed"])
    pass_rate  = passed / len(results)
    avg_acc    = sum(r["accuracy"] for r in results) / len(results)
    avg_hall   = sum(r["hallucination_risk"] for r in results) / len(results)

    print(f"{'='*60}")
    print(f"  RESULTS: {passed}/{len(results)} passed ({pass_rate*100:.0f}%)")
    print(f"  Avg accuracy:          {avg_acc:.1f}/10")
    print(f"  Avg hallucination risk: {avg_hall:.1f}/10")
    print(f"  Threshold:             {EVAL_PASS_THRESHOLD*100:.0f}%")

    if pass_rate >= EVAL_PASS_THRESHOLD:
        print(f"  STATUS: ✓ PASS")
    else:
        print(f"  STATUS: ✗ FAIL — below {EVAL_PASS_THRESHOLD*100:.0f}% threshold")
        import sys; sys.exit(1)   # CI gate
    print(f"{'='*60}\n")
    return results


if __name__ == "__main__":
    run_evals()

Future — multi-agent travel planner

The ChatService, tool registry, and router you built are already plug-and-play. The travel agent just instantiates them with a different project_id.

A
Agent A — Researcher
Searches flights, hotels, and attractions using web search + price APIs. Stores findings in ChromaDB under project_id="travel". Same tool registry pattern as Phase 1.
B
Agent B — Coordinator (+ Google Calendar MCP)
Decomposes the travel request, calls Agent A for research, queries Google Calendar MCP to check for conflicts, merges results into a structured plan.
C
Agent C — Booker (human-in-the-loop)
Formats the itinerary and sets session status to awaiting_approval. Execution pauses. User sees the plan and types Confirm / Edit / Reject. Only on Confirm does Agent C proceed to book.
Human-in-the-loop is a state machine. Add a status column to the messages table: running → awaiting_approval → confirmed / cancelled. The ChatService checks status before processing the next message. This pattern is directly reusable for any approval workflow.
